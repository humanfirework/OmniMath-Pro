# OmniMath 架构与重构决策

> 目标：桌面优先、后续 Android 手机/平板，一套代码；启动快、内存小、手写流畅、界面简洁。
> 本文只记录**决策与理由**，不重复功能清单。最后更新：2026-11。

## 1. 技术栈结论

**保留 Tauri 2 + React 19 + TypeScript + Canvas 2D，不迁移 GPUI，也不整体重写为 Flutter。**

| 方案 | 结论 | 原因 |
| --- | --- | --- |
| Tauri 2 + React + Canvas（现状） | **采用** | 一套代码覆盖 Windows/macOS/Linux，Tauri 2 已支持 Android/iOS；数学排版（KaTeX）、代码编辑器（CodeMirror）、3D（three.js）生态完整；安装包与内存占用远小于 Electron。 |
| GPUI | **否决** | Rust 原生、桌面-only，API 仍在快速变动；没有 Android 路径；迁移意味着放弃 KaTeX/CodeMirror/three.js/React 生态，等于重写。性能瓶颈不在框架，而在渲染循环。 |
| Flutter + Rust | **暂不采用** | UI 一致性好，但数学排版、公式编辑、代码编辑器、3D 都要重新选型；是完整重写，无法在现有代码上渐进交付。 |
| 原生三端（WinUI/Compose/SwiftUI） | **否决** | 三套代码、三套渲染与输入逻辑，维护成本最高，与"三端统一"目标冲突。 |

### 什么时候才考虑 GPUI

只有当产品明确变成**桌面-only 的专业手写工具**，且实测 Canvas 在 240Hz 笔输入下无法达标时，才值得评估。当前没有证据支持这一点。

## 2. 性能真正的瓶颈与对策

历史卡顿的根因不是 Canvas，而是：

1. 每个 pointermove 都触发 React state 更新；
2. 用 SVG/DOM 承载笔迹，节点数量随笔画线性增长；
3. 每次移动重绘全部历史笔画；
4. 3D 视图在启动时就创建 WebGL 上下文。

现在的渲染架构：

- **四层 Canvas**：背景网格 / 已提交笔迹 / 当前笔迹 / 选择与套索覆盖层。
- **增量绘制**：当前笔画只追加新段；提交后转为 `Path2D` 缓存。
- **RDP 简化 + 可变宽度轮廓**：减少点数，保留压感。
- **DPR 上限 2**：高分屏不盲目 3x/4x 放大。
- **3D 懒挂载**：首次进入 3D 标签才创建 WebGL 上下文。
- **面板/视图懒加载**：大模块按需 import。

后续如果笔迹规模超过 2 万条或需要 240Hz：

1. 已提交层移到 `OffscreenCanvas` + Worker；
2. 用 WebGL2 实例化四边形绘制笔迹；
3. 仍不引入 GPUI——只是换渲染后端。

### 性能预算（验收口径）

| 指标 | 目标 |
| --- | --- |
| 冷启动到可交互 | ≤ 3s（桌面） |
| 面板切换 | ≤ 16ms |
| 笔迹输入到上屏 | ≤ 16ms（平板实测） |
| 1000 条笔迹缩放/平移 | 稳定 60fps |
| 桌面常驻内存 | ≤ 400MB |
| Windows 安装包 | ≤ 80MB |

### 当前实测基线（Chromium headless，1440×900，1000 条笔迹）

| 指标 | 实测 |
| --- | --- |
| 首次可交互 | 0.95s |
| 打开含 1000 条笔迹的白板 | 0.72s（一次性，之后驻留） |
| 连续缩放平均帧时间 | 16.6ms（≈60fps） |
| 缩放 P95 帧时间 | 20.1ms |
| 鼠标输入→下一帧（探针） | 平均 9.2ms · P95 15.7ms |

白板“更多 → 笔迹延迟测试”内置探针，可在真实平板上直接读取输入延迟分布。

测量脚本不进入仓库，数据仅用于回归对比。后续用同一脚本跟踪 P95 与内存。

## 3. 三端策略

- **一套 React 代码 + 响应式外壳**：桌面是紧凑活动栏 + 可调整分栏；平板是"画布优先 + 浮动笔栏"；手机是底部 4 标签（侧栏/编辑器/画布/预览）。
- **Android 路线**：Tauri 2 mobile 先跑通；用真实设备测笔输入延迟。如果 WebView 的 pointer 链路超过 16ms，再写一个原生插件，直接接 Android `MotionEvent`/Ink API，把采样点批量送入 Canvas 引擎。**先测量，再决定是否下沉原生**。
- **PWA 兜底**：同一份静态产物可直接部署为网页版，方便分享与快速验证。
- 平板手写工具：钢笔/马克笔/荧光笔、点擦/划擦、套索多选、无限画布、50 步撤销、双指缩放。后续补倾斜与套索缩放。

## 4. 手写数学（Math Notes）流水线

严格按已验证的顺序：**先准确，再快**。

```
笔迹 → 按空间分组为符号 → 本地符号分类 → 二维结构还原（上标/分数）
     → 表达式规范化 → mathjs 求值 / 采样 → 矢量图像对象
```

已落地：

- 笔迹分组：交叉笔画合并（+、×、=），行内基线聚类；
- 符号分类：字体骨架模板（Zhang–Suen 细化 + Chamfer 距离）+ 几何规则（+ − = / × · ( ) 0 1 2 3 6 7 8 9 y）；
- 二维结构：上标识别、分数（宽横线 + 上下分组）、隐式乘法、`y=` / `f(x)=` 解析、x/× 上下文消歧；
- 计算与绘图：安全白名单求值、600 点采样、可拖动/滚轮缩放的矢量图像卡；
- 结果字形：优先复用用户自己写过的字形，缺失字符才回退手写风格字体；
- 交互：停笔约 1 秒识别，结果可编辑，识别错误可修正后插入。

下一阶段：

1. **个人字形库**：用户修正后把该字形写入本地模板库，越用越准（本地自适应，不上传）；
2. **专用小模型**：用 CROHME 类数据训练/蒸馏一个 1–3MB 的 ONNX 符号分类器，替换字体模板；仍在本机运行；
3. **结构增强**：分数、根号、上下标组合、矩阵；
4. **可选云端识别**：MyScript/Mathpix 作为 BYOK 备选，默认关闭。

**不使用大模型做识别。** 识别是低延迟、确定性任务，大模型既慢又不可控。

## 5. AI 的嵌入方式

AI 是**动作层**，不是又一个聊天页：

- 选中公式/笔迹/代码 → 浮动动作：解释、纠错、等价变形、生成图像、出练习题；
- 命令面板输入自然语言 → 解析为结构化动作（例如"把这段画成 3D 曲面"）；
- 默认 BYOK（OpenAI 兼容端点），密钥只存本地；
- 无密钥时提供确定性本地动作（化简、求导、绘图、单位换算）；
- 任何上传都需要显式确认，默认不发送整篇笔记。

已落地：数学笔记面板提供「AI 解释」按钮，只把当前识别出的表达式/结果发给用户已配置的端点；无密钥时给出配置提示，不上传任何内容。AI 侧边面板已支持上下文注入与工作台工具调用。

## 6. 云端与多端同步

**本地优先（local-first），云端是同步层，不是数据源。**

数据模型：

```
Workspace
 ├─ notes / boards / scripts / assets
 └─ 每条记录：{ id, type, updatedAt, rev, deleted, payload }
```

阶段：

1. **快照同步（已落地）**：本地导出/导入 JSON；桌面版可直接写入 OneDrive/iCloud/Dropbox/Syncthing 等已同步文件夹，另一台设备读取同一文件即可迁移。无需账号或服务器。
2. **记录级同步（已落地）**：合并时历史/绘图/曲线集按 id 取并集，变量按名称补全，冲突保留本机；不是实时推送。
3. **零后端云同步（已落地）**：可选 GitHub Gist——用户填个人 Token（仅 gist 权限），工作区上传为私有 Gist，另一台设备用同一 Token 读取；Token 只存本机且不进入快照。适合没有自建服务器的场景。
4. **CRDT**：只在需要多人实时协作时引入（Yjs/Automerge），个人多设备不必一开始就付出复杂度。

不引入自建账号体系也能先用：桌面版选择任意已同步文件夹，或用 Gist；实时推送 / WebDAV / 托管服务后续再加。

## 7. 蓝图与傅里叶

傅里叶描述子（Fourier descriptors）是**形状特征**：对轮廓做 DFT，取低频幅值，得到旋转/缩放较稳定的形状签名。它适合：

- 手绘节点形状分类（矩形/菱形/椭圆/三角形/箭头）；
- 去噪、平滑、相似形状检索；
- 与拓扑分析结合，判断"哪些形状构成了图"。

它**不能**从任意截图里推断语义（例如"这是一个快速排序流程图"）。蓝图识别要分两层：

1. 视觉层：形状 + 连线 + 文字区域；
2. 语义层：图结构 + 标签 + 规则/模型。

先做视觉层的稳定识别，再谈语义。不要把傅里叶当成万能识别器。

已落地：`src/lib/vision/shapeFourier.ts` 对轮廓做等弧长重采样与 DFT，取归一化低频幅值作为旋转/缩放不变签名，已作为白板手绘形状识别的兜底，并接入蓝图 `shape-classify` 节点：

- 输入：`contour-trace` / `fine-outline` 的折线集；
- 过滤：按周长丢弃噪点、按包围盒面积保留最大的 N 个、按置信度过滤；
- 输出：逐条形状标注 + 计数 + 本地化摘要；轮廓透传 `shape` 元数据，
  标签随 `curve-fit → plot-curves` 完成像素→数学坐标变换，结果面板在图形中心绘制标签；
- 蓝图 `blueprint-parse` 节点：视觉层提取节点框（矩形/椭圆/圆）与连线。空心框取内孔作为节点，跳过外侧重复边框环；连线要求两端分别靠近两个不同节点。结果面板用 N1/N2 标注节点，输出 graph 数据（nodes/links）。不识别文字标签；
- 边界：仍只是视觉层形状/连接特征，不做语义识别（不判断这是流程图还是电路图）。

## 8. 目录与模块边界

```
src/lib/ink/          Canvas 墨迹引擎（与 React 无关，可 Worker 化）
src/lib/mathnotes/    表达式引擎 + 本地符号识别
src/lib/engine/       共享 mathjs 实例、求值、符号运算
src/lib/plots/        2D/3D 采样与渲染；curveTypes.ts 只放曲线/贝塞尔类型，供 store、vision 与组件共用
src/components/workbench/
  layout/             标题栏、活动栏、侧栏、编辑器、预览、状态栏
  whiteboard/         白板与数学卡片
  studio/             首页与各学科轻量入口
  nodes/              蓝图/流水线
```

原则：**纯逻辑不进 React 组件**；引擎可单测、可 Worker、可复用到手机端。

  - Studio 首页、紧凑矩阵实验室；新用户默认落在 Studio 首页而不是代码编辑器；
  - Math Notes MVP：手写 `2+3`、`y=x^3` → 计算/图像卡；
  - 个人字形库（高置信本地自适应）；
  - 修复并排视图高度为 0、3D 启动即建 WebGL、状态栏/编辑器重复信息；
  - 工作台先加载 + 短启动动画（可交互 5.9s → 0.95s）；
  - PWA 清单与图标、墨迹视口裁剪、傅里叶形状兜底；
  - 蓝图 `shape-classify` 节点：傅里叶形状特征（圆/椭圆/矩形/三角形）接入轮廓管线，结果面板标注图形类型；
  - 蓝图 `blueprint-parse` 节点：节点框（空心取内孔、去重边框环）+ 连线（两端吸附到两个节点），结果面板 N1/N2 标注，附「手绘蓝图识别」模板；
  - 手机端：首页标签 + 全宽工具视图（矩阵/蓝图/统计等可进入，返回键回到四标签工作台）；
  - 桌面全屏视图标题栏可一键隐藏编辑器，节点卡片默认折叠配置、保留结果摘要；
  - 全屏工具视图（白板/蓝图/矩阵/求解/统计/控制/学习）进入时自动收起代码编辑器、工具占满窗口，返回工作台时恢复；编辑器隐藏时状态栏不再显示「N 行 · 模式」；
  - 3D 视图按场景包围盒自动取景（之前固定相机距离，默认 [-5,5] 曲面边缘被裁掉），雾随取景距离缩放；
  - 编辑器工具栏容器查询自适应：面板变窄时模式切换收为下拉、隐藏统计与重置/清空，运行按钮保留；
  - 标题栏「文件/编辑/视图/帮助」改为真实下拉菜单：打开文件浏览器、运行/清空/符号面板、面板显隐与主题、命令面板/快捷键/关于；打开文件与运行脚本走现有 store 与事件，不新增耦合；
  - 手绘图形识别默认开启；修复矩形误差把框内点计为 0 导致圆/正方形被误判为矩形的问题，判定抽成 `src/lib/ink/shapeRecognize.ts` 并补单测（圆、正方形、长方形、三角形、直线）；
  - 「恢复默认设置」同时清除 `react-resizable-panels:*` 缓存的面板尺寸（之前重置后分栏仍停留在被拖坏的比例）；
  - 白板偏好跨会话保留：笔刷、颜色、线宽、形状识别开关、数学模式写入 settingsStore（刷新后自动恢复）；笔画落盘改为 350ms 防抖，并在卸载 / 页面隐藏前 flush，大画布连续书写不再每笔同步序列化；
  - Studio 首页在手机端预留底部空白，滚到底时卡片不会被悬浮计算器遮住；
  - 编辑器交互修正：Enter 正常换行、Ctrl/Cmd+Enter 运行（全局「运行」快捷键同步迁移）；Tab/Shift+Tab 缩进不再把焦点移出编辑器；清空内容后编辑器不再被「没有打开的文件」空状态替换，空编辑器显示占位示例；
  - 编辑器选区动作条：选中代码后在选区旁浮出「运行 / 解释 / 简化 / 画图」，运行只执行选中行（手机端执行后自动切到预览）；解释与简化把选区打包成 prompt 送入 AI 面板（自动切到 AI 标签并保证预览可见），画图在本地解析 `f(x)` / `y = f(x)` 直接生成 2D 曲线，不需要 API Key；动作条按编辑器容器边界定位，避开工具栏，点击外部自动收起；
  - 修复 2D 绘图与分面图空白：卸载（含 React StrictMode 的假卸载）取消 rAF 后没有复位「已排队」标记，重新挂载后再也不会调度重绘，canvas 停在默认 300×150；现在卸载时同时清空 raf id 并复位标记，曲线 / 网格恢复；
  - 修复 3D 曲面被拉成长带：脚本 `plot3d(...)` 之前把 2D 的 yRange `[-50,50]` 当成自变量 y 的定义域；现在 3D 的 x / y 使用同一范围（`buildPlotConfig` 收口并补单测），sin(x)cos(y) 恢复成正常的波浪曲面；
  - 手机端白板去重：顶部只保留「白板 / 数学模式 / 更多」，工具、颜色、线宽统一由底部浮动笔栏承担，窄屏不再出现两套重复控件、工具栏也不再折成两行；
  - 手机端侧边面板补上横向面板标签条（历史 / 变量 / 文件 / 公式库 / 线代 / 求解 / 统计）与关闭按钮，之前手机没有活动栏、只能停在单一面板；
  - 手机端从选区「画图 / 解释」会自动切到「预览」标签（解释还会切到 AI）；AI 标签激活时隐藏悬浮计算器，不再压住输入框与发送键；
  - 历史记录「载入编辑器」会确保编辑器真的可见：桌面端编辑器被隐藏时自动展开，手机端直接切到编辑器标签（之前内容写进去了，但用户还停在侧栏）；
  - 命令面板补齐「工具视图」分组（首页 / 工作台 / 白板 / 蓝图 / 线代 / 求解 / 统计 / 控制 / 学习），与活动栏使用同一套本地化名称，中文、英文都能直接搜到；移除硬编码的 Workbench / Pipeline 条目；
  - 手机端可进入设置：语言菜单新增「设置」，命令面板也新增「设置」命令（之前手机没有菜单栏，设置入口完全不可达）；设置 / 命令面板打开时悬浮计算器自动让位；
  - 「运行到独立浮窗」：脚本（或编辑器选区）可运行到可拖动的独立结果浮窗，而不是挤进预览面板；入口在标题栏「编辑」菜单与命令面板（中英文都可搜）；浮窗宿主 `RunResultsHost` 从蓝图视图提升到 Workbench 全局挂载，桌面 / 手机 / 手机全屏三个分支都能用，初始位置避开标题栏（手机上为 260px 宽，按屏幕左上角偏移层叠）；
  - 首屏不再加载 mathjs：`EditorPanel / PreviewPanel / SidePanel / SettingsPanel` 改为按需加载（`LazyPanels`），工作台 store 的变量恢复 / 删除 / 清空改用动态导入，采样默认值与结果精度拆到 mathjs-free 的 `plotDefaults.ts` / `formatDefaults.ts`；首屏 JS 由约 2.54 MB 降到约 0.98 MB（gzip 约 0.77 MB → 0.31 MB），Studio 首页、悬浮计算器、白板、手机五标签均不再等待 mathjs；首次进入工作台或第一次求值时才下载引擎；
